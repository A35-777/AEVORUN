Research Background

Why Learned Temporal Prioritization?

Date and time logic is notoriously deceptive. Here is the academic context, empirical motivation, and technical design philosophy behind AEVORUN.

The Academic Motivation

In a landmark empirical investigation of 1,000+ Python date/time bugs presented at ACM SIGSOFT / IEEE MSR 2025 (Tiwari et al., "Time Will Tell: An Empirical Study of Date and Time Bugs in Python"), researchers observed that temporal defects frequently slip past existing test suites because unit tests pass during standard development dates and fail abruptly on temporal boundaries.

Why Existing Tools Fail

Static linters (like flake8-datetimez) enforce naive checks (e.g. banning naive datetime objects) but cannot reason about calendar arithmetic or leap day mutations. LLM test generators hallucinate unnecessary tests, require network calls, and are too slow and expensive for pre-commit hooks.

Core Design Principles

1. Zero Pretrained Weights

AEVORUN-T1 is trained completely from scratch without using OpenAI, Anthropic, or Hugging Face pretrained models. All 53,711 parameters originate from our supervised training pipeline.

2. 100% Offline CPU Execution

Inference takes 0.07 milliseconds per function on standard consumer CPUs. No GPU, no internet connection, and no API keys are required.

3. Negative-Class Calibration

A crucial flaw in test recommenders is recommending tests for everything. AEVORUN-T1 was trained with hard negative examples to ensure zero false positives on non-temporal code.
