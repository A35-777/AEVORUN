Scenario Taxonomy

14 Canonical Temporal Failure Modes

AEVORUN-T1 maps Python source code ASTs to a calibrated multi-label ranking across these 14 edge-case categories.

Scenario 01

leap_day (February 29)

Failure Mode: Invoking d.replace(year=d.year + 1) or incrementing contract periods raises ValueError: day is out of range for month when evaluated on a leap day.

# Buggy pattern:
next_anniversary = birth_date.replace(year=today.year)
# Test strategy: Pass date(2024, 2, 29) and assert fallback to Feb 28.
Scenario 02

month_end (28th - 31st Rollover)

Failure Mode: Months have variable lengths. Adding a fixed 30-day timedelta causes end-of-month invoice schedules to drift backward in March and skip August/October 31st.

# Buggy pattern:
next_invoice = invoice_date + timedelta(days=30)
# Test strategy: Test starting on Jan 31, assert next is Feb 28/29.
Scenario 03

daylight_saving_transition (Spring / Fall Jumps)

Failure Mode: Clocks skip forward 1 hour in spring (creating non-existent times) and fall back 1 hour in autumn (creating repeated times). Naive arithmetic corrupts scheduled jobs.

# Buggy pattern:
scheduled_run = last_run + timedelta(hours=24)
# Test strategy: Run across DST boundary in America/New_York (23h or 25h day).
Scenario 04

ambiguous_local_time (Fold 0 vs. 1)

Failure Mode: During autumn fall-back transitions, times between 01:00 and 02:00 AM occur twice. Code failing to specify fold=0 or fold=1 produces undefined sorting order.

# Buggy pattern:
is_first_occurrence = (local_dt.fold == 0) # Ignored in naive sorting
# Test strategy: Compare datetime(2024, 11, 3, 1, 30, fold=0) vs fold=1.
Scenario 05

nonexistent_local_time (Civil Clock Gap)

Failure Mode: In spring forward, times between 02:00 and 03:00 AM do not exist. Instantiating a naive datetime and converting with ZoneInfo leads to surprising offset choices.

# Buggy pattern:
meeting = datetime(2024, 3, 10, 2, 30, tzinfo=ZoneInfo("America/New_York"))
# Test strategy: Probe existence of civil time; expect normalized 03:30 AM.
Scenario 06

naive_aware_mismatch (TypeError)

Failure Mode: Comparing or subtracting a naive datetime with a timezone-aware datetime raises TypeError: can't compare offset-naive and offset-aware datetimes.

# Buggy pattern:
if user_input_time < datetime.now(timezone.utc): # TypeError if naive!
# Test strategy: Pass naive input; assert explicit timezone coercion.
Scenario 07

timestamp_precision (Sub-Second Truncation)

Failure Mode: Floating point Unix timestamps lose precision at microsecond/nanosecond scales. Comparing timestamps with == after JSON serialization fails.

# Buggy pattern:
assert round(ts1, 3) == round(ts2, 3)
# Test strategy: Test microsecond boundary values: .999999 vs .000001.
Scenario 08

calendar_duration_mismatch (Duration != Calendar)

Failure Mode: Treating calendar units as uniform physical durations. 1 month is not 30 days, 1 year is not 365 days, and 1 day is not always 86,400 seconds.

# Buggy pattern:
duration_seconds = months * 30 * 86400
# Test strategy: Compare elapsed wall-clock calendar interval vs epoch delta.
Scenario 09

year_boundary (Dec 31 to Jan 1)

Failure Mode: ISO week year formatting (%G-%V) differs from calendar year (%Y) around Dec 29 - Jan 3, causing log files or metrics buckets to overwrite previous years.

# Buggy pattern:
partition_key = dt.strftime("%Y-week-%W")
# Test strategy: Test on Dec 31, 2024 and Jan 1, 2025.
Scenario 10

midnight_boundary (23:59:59 to 00:00:00)

Failure Mode: Off-by-one errors on day boundaries, inclusive vs. exclusive ranges, and date queries using <= 23:59:59 that miss records in the last second.

# Buggy pattern:
query = select().where(created_at <= end_date.replace(hour=23, minute=59))
# Test strategy: Probe boundary at 23:59:59.999999.
Scenario 11

timezone_conversion (Offset Errors)

Failure Mode: Applying fixed UTC offset arithmetic (e.g. + timedelta(hours=5)) instead of IANA tzdb rules, ignoring historical offset adjustments and policy changes.

# Buggy pattern:
ist_time = utc_time + timedelta(hours=5, minutes=30)
# Test strategy: Convert using ZoneInfo("Asia/Kolkata") across historical dates.
Scenario 12

date_parsing (Ambiguous Locales)

Failure Mode: Inconsistent DD/MM/YYYY vs. MM/DD/YYYY parsing without explicit format specifications causes silent transpositions for dates like 03/04/2024.

# Buggy pattern:
dt = datetime.strptime(raw_str, "%m/%d/%Y") # Fails on EU dates
# Test strategy: Test day <= 12 where month and day are interchangeable.
Scenario 13

recurring_schedule (Phase Accumulation)

Failure Mode: Re-computing scheduled run times by adding duration to previous execution time causes cumulative execution delay (phase drift) under load.

# Buggy pattern:
next_tick = last_tick_finished_at + interval
# Test strategy: Simulate execution jitter and verify alignment with epoch ticks.
Scenario 14

expiration_boundary (TTL & Sessions)

Failure Mode: Clock skew between distributed servers causing JWTs or cache keys to expire prematurely or remain valid after expiration.

# Buggy pattern:
is_expired = now > expires_at # No clock skew grace window
# Test strategy: Probe delta = 0 and delta = -1 with simulated clock skew.
